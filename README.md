# مِفتاح الطب · MedKey Gulf 🗝
> نفهمك الطب من جذوره — منصة تعليم طبي تأسيسي

منصة تعليم طبي لطلاب السنة الأولى في السعودية والخليج، مبنية على **المفاهيم الكلية** (مفاتيح الطب) قبل التفاصيل، مع مرشد ذكي (RAG) يجيب من مصادر مفتوحة موثّقة.

`Next.js 15 · TypeScript · Prisma · PostgreSQL/pgvector · Anthropic`

---

## ماذا يعمل الآن؟
- ✅ واجهات RTL كاملة (رئيسية، مسارات، مفاتيح، درس بالبنية الـ14، أسئلة تفاعلية، مرشد) + وضع ليلي.
- ✅ منهج حقيقي مبذور: 16 مفتاحًا، 17 مسارًا، دروس نموذجية، أسئلة بشرح وسبب خطأ، بطاقات، مصطلحات، خرائط.
- ✅ Prisma schema بالـ27 جدولًا مع pgvector.
- ✅ طبقة ربط **فعلية** بالمصادر المفتوحة: MedlinePlus (NLM)، PubMed (NCBI E-utilities)، OpenStax (CC BY).
- ✅ مرشد طبي: حارس سلامة + RAG + Anthropic Messages API + سجل استشهادات.

> الواجهة والمنهج يعملان **فورًا** دون قاعدة بيانات (يقرأان من `src/lib/curriculum.ts`).
> قاعدة البيانات والمرشد يُفعَّلان بخطوات الإعداد أدناه.

## التشغيل السريع (واجهة + منهج فقط)
```bash
npm install
npm run dev            # http://localhost:3000
```

## التشغيل الكامل (قاعدة بيانات + مرشد + مصادر)
```bash
cp .env.example .env               # ثم عبّئ ANTHROPIC_API_KEY
docker compose up -d               # PostgreSQL + pgvector محليًا
npm run db:push                    # إنشاء الجداول
npm run db:seed                    # بذر المنهج (16 مفتاح، مسارات، دروس، أسئلة)
npm run ingest                     # (اختياري) جلب مصادر مفتوحة إلى قاعدة البيانات
npm run dev
```

### تفعيل البحث الدلالي pgvector (اختياري)
1. فعّل الامتداد: `CREATE EXTENSION IF NOT EXISTS vector;` (صورة `pgvector/pgvector` تتضمنه).
2. اضبط `EMBEDDINGS_PROVIDER=voyage` و`VOYAGE_API_KEY`، ثم أضِف حساب التضمين في `ingest.ts`.
3. حدّث `retrieve()` في `src/lib/rag.ts` لاستخدام عامل `<->` على عمود `embedding`.
> بدون تضمينات: يعمل الاسترجاع بالبحث النصّي الكامل (fallback) — لا يتعطّل شيء.

## ضمان الجودة والمراجعة العلمية (بوابة «لا سؤال غير صحيح»)
بنك الأسئلة الحالي: **38 سؤالًا تأسيسيًا مُحقّقًا** على حقائق علمية قطعية غير خلافية، كل سؤال بإجابة صحيحة واحدة + سبب خطأ لكل خيار + شرح + ربط بمفتاح + مصدر.

**طبقتان تمنعان وصول أي سؤال غير سليم للطالب:**
1. **مُدقّق آلي**: `npm run qa` — يرفض أي سؤال بلا إجابة صحيحة، أو بأكثر من إجابة، أو بخيار بلا تفسير، أو بشرح ناقص. يخرج بكود 1 عند أي خلل (صالح لـ CI).
2. **مراجعة بشرية**: كل سؤال يبدأ `reviewStatus = pending`. لوحة `/admin/review` تعرضه للمُراجع (دور REVIEWER) ليعتمد أو يرفض. `/api/questions` يخدم **المعتمد فقط** للطالب؛ وقبل الاعتماد تظهر شاشة الأسئلة شارة «قيد المراجعة العلمية».

> ⚠️ المحتوى الطبي يتطلّب اعتماد خبير قبل الاستخدام الفعلي مع الطلاب. النظام يفرض ذلك بنيويًا.
> المُراجع الافتراضي بعد البذر: `reviewer@miftah.example` (دور REVIEWER).
