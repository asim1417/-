# legal-search-audit

أداة فحص ومقارنة احترافية (Audit) لمحرّكَي البحث القانونيَّين السعوديَّين
**قانونية** (qanoniah.com) و**قسطاس** (qistas.com/ar)، مبنية بـ TypeScript + Playwright.

> **الفلسفة:** هذه أداة **وصفية وتحليلية** لتجربة المستخدم والبحث والعناصر
> الظاهرة فقط. **ليست** أداة كشط محتوى ولا تجاوز اشتراكات ولا تجميع قواعد بيانات.

---

## 1) فكرة المشروع والغرض منه

إجراء فحص مهني شامل وموضوعي للموقعين من حيث: تجربة البحث، جودة النتائج،
الواجهات، التنقل، الأيقونات، صندوق البحث، الفهارس، الفلاتر، صفحات النتائج
والتفاصيل، الأداء، الجوال، إمكانية الوصول، SEO، والثقة القانونية — ثم إنتاج
تقارير قابلة للتنفيذ تساعد على **بناء محرك بحث قانوني سعودي أفضل**.

النتيجة النهائية: تقريران HTML (مقارنة شاملة + تقرير UX بصري)، مجموعة ملفات
JSON تفصيلية، ملخص CSV قابل للفرز، ولقطات شاشة منظمة.

---

## 2) القيود القانونية والأخلاقية (مهم جدًا)

الأداة مصمَّمة منذ جذورها لتحترم الضوابط التالية، وهي مفروضة في الكود وليست
مجرد توصيات:

- **تحترم `robots.txt`** قبل كل طلب (`core/robotsCheck.ts`)، ولا تجلب أي مسار
  ممنوع (`Disallow`).
- **معدل طلبات منخفض وآمن** افتراضيًا (~طلب كل 7 ثوانٍ، قابل للضبط 5–10 ثوانٍ).
- **تتوقف فورًا** عند ظهور كابتشا / حظر / جدار اشتراك / طلب تحقق / 403 / 429
  (`core/safetyGuard.ts`) — ولا تحاول تجاوز أي حماية إطلاقًا.
- **لا تسجّل إلا الظاهر للمستخدم**: عنوان، نوع مصدر، رابط، مقتطف قصير (مقصوص)،
  رقم مادة/اسم نظام إن ظهرا، ترتيب النتيجة، زمن الاستجابة، لقطة شاشة.
- **لا تحمّل النصوص الكاملة** للأحكام أو الأنظمة (المقتطفات مقصوصة إلى ≈220 حرفًا).
- **لا تستخدم أي حساب** إلا إذا زوّدتها بحساب **مصرّح** عبر `.env` (اختياري تمامًا).
- **هوية شفافة**: تستخدم User-Agent وصفيًا غير مضلِّل.

**ما لا تفعله الأداة نهائيًا:** نسخ قواعد البيانات · تحميل كميات كبيرة من النصوص ·
تجاوز الاشتراك أو الحماية · تجاهل robots.txt · طلبات كثيفة · إخفاء هوية مضلِّل ·
استخدام بيانات دخول غير مصرّح بها.

## 3) التثبيت

المتطلبات: Node.js 18+.

```bash
cd legal-search-audit
npm install
# تنزيل متصفح Chromium الخاص بـ Playwright (مطلوب مرة واحدة):
npx playwright install chromium
```

> ملاحظة: في بيئات مقيّدة الشبكة قد يفشل تنزيل المتصفح تلقائيًا؛ نفّذ الأمر
> `npx playwright install chromium` يدويًا على جهاز يسمح بالوصول إلى
> `cdn.playwright.dev`.

اختياريًا انسخ ملف البيئة:

```bash
cp .env.example .env   # كل القيم اختيارية؛ الأداة تعمل بدونه
```

## 4) طريقة التشغيل

```bash
# عبر ts-node مباشرة (بدون بناء):
npm run audit -- --targets qanoniah,qistas --queries ./data/legal_queries.csv \
  --headless true --output ./reports

# أو بعد البناء:
npm run build
node dist/index.js --targets qanoniah,qistas --output ./reports
```

تجربة سريعة (عدد محدود من الاستعلامات + كل المقاسات):

```bash
npm run audit -- --maxQueries 5 --viewport all --headless false
```

## 5) خيارات سطر الأوامر (CLI)

| الخيار | الوصف | الافتراضي |
|---|---|---|
| `--targets` | قائمة المواقع مفصولة بفواصل | `qanoniah,qistas` |
| `--queries` | مسار ملف الاستعلامات CSV | `./data/legal_queries.csv` |
| `--headless` | تشغيل بدون نافذة `true/false` | `true` |
| `--output` | مجلد حفظ التقارير | `./reports` |
| `--maxQueries` | حدّ عدد الاستعلامات (تجربة سريعة) | الكل |
| `--saveScreenshots` | حفظ لقطات الشاشة `true/false` | `true` |
| `--viewport` | `desktop` \| `mobile` \| `all` | `desktop` |
| `--delayMs` | مدة الانتظار بين الطلبات (ملّي ثانية) | `7000` |
| `--stopOnBlock` | إيقاف الموقع عند منع/كابتشا | `true` |
| `--pageTimeoutMs` | مهلة كل صفحة | `45000` |
| `--fresh` | حذف تقارير سابقة قبل التشغيل | `false` |

> الخيارات تتجاوز متغيرات `.env`، والتي بدورها تتجاوز القيم الافتراضية في
> `src/config.ts`.

## 6) تعديل الـ selectors والروابط

كل الروابط والـ selectors في ملفات مستقلة **ولا توجد selectors ثابتة داخل منطق
الفحص**:

- `src/targets/qanoniah.ts` و`src/targets/qistas.ts`: روابط كل موقع وصفحاته
  والـ selectors الخاصة به.
- `src/config.ts`: يجمع الأهداف ويحدّد المقاسات (Viewports) والإعدادات الافتراضية.

إذا تركت أي selector فارغًا (`""`) فستعتمد الأداة على **حلول مرنة** تلقائيًا:
النص الظاهر، `aria-label`، `role`، `placeholder`، وقواعد CSS heuristic
(`role=searchbox`، `input[type=search]`، أنماط بطاقات النتائج… إلخ). كما يوجد
مسار احتياطي يكتب الاستعلام في صندوق البحث الحي ويضغط Enter إذا فشل الانتقال
المباشر عبر رابط البحث.

## 7) إضافة موقع جديد

1. أنشئ `src/targets/myTarget.ts` يصدّر `TargetConfig` (انظر ملفات الأهداف الحالية).
2. أضِفه في `src/config.ts` داخل كائن `TARGETS`.
3. شغّل: `--targets myTarget`. لا حاجة لتعديل أي منطق فحص — الكود لا يكرّر نفسه
   بين المواقع.

---

## 8) إضافة استعلامات جديدة

عدّل `data/legal_queries.csv` بالأعمدة:

```
id,category,query,expected_intent,expected_sources,notes
```

`category` يقابل أنواع الفحص: `literal`, `article_number`, `natural_question`,
`semantic`, `spelling`, `numerals`, `diacritics_hamza`. يُستنتج النوع تلقائيًا
إن لم يُحدَّد. الملف الحالي يحتوي 40 استعلامًا سعوديًا متنوعًا يغطي البحث اللفظي،
رقم المادة، الأسئلة الطبيعية، الدلالي، الأخطاء الإملائية، الأرقام الهندية،
والهمزات/التشكيل.

## 10) نظام التقييم (4 بطاقات مستقلة من 100)

كل بطاقة تُحسب بمعايير شفّافة وقابلة لإعادة الإنتاج (`src/core/scoring.ts`):

1. **البحث**: جودة النتائج (30) · دقة الوصول للمادة/النظام (20) · الفلاتر والتنقل (15)
   · الأداء والسرعة (15) · تجربة RTL (10) · الشفافية والمصدر (10).
2. **تجربة المستخدم (UX)**: الرئيسية (10) · صندوق البحث (15) · صفحة النتائج (15) ·
   الفلاتر (10) · الفهارس (15) · صفحات التفاصيل (10) · الأيقونات (5) · التنقل (10) ·
   الجوال (5) · الاتساق وRTL (5).
3. **الثقة القانونية**: المصادر الرسمية (20) · تواريخ الإصدار/التحديث (15) · حالة
   السريان (15) · الربط بين المصادر (20) · وضوح نوع المحتوى (10) · التحقق من الأصل (10)
   · التنبيهات/الحدود (10).
4. **الأداء**: الرئيسية (20) · البحث (25) · فتح النتائج (20) · الجوال (15) ·
   حجم الموارد (10) · قلة الأخطاء (10).

**مقياس جودة النتيجة (0–5):** أولى مطابقة تمامًا=5 · ضمن أول 3=4 · ضمن أول 5=3 ·
قريبة غير مباشرة=2 · عامة=1 · لا نتيجة=0.


## 13) المشاكل المتوقعة وكيفية التعامل معها

- **فشل تنزيل متصفح Playwright**: نفّذ `npx playwright install chromium` على شبكة
  مسموح بها.
- **اختلاف مسارات البحث/الصفحات عن الواقع**: حدّث `searchUrl` و`pages` في ملف
  الهدف. الأداة تتدهور بأمان (تجرّب الكتابة في صندوق البحث الحي) ولا تتوقف.
- **selectors غير مستقرة**: اتركها فارغة لتعمل الـ heuristics، أو املأها بعد
  التحقق من الموقع.
- **ظهور كابتشا/حظر**: الأداة **تتوقف تلقائيًا** عن ذلك الموقع وتسجّل السبب
  (مع `--stopOnBlock true`)، وتُكمل بقية المواقع. هذا سلوك مقصود — **لا تحاول
  تعطيله للالتفاف على الحماية**.
- **نتائج فارغة لموقع**: غالبًا بسبب جدار اشتراك أو selector غير صحيح؛ راجع
  `results.json` و`_partial/` واللقطات.

## 14) حدود ما لا تقوم به الأداة

- لا تتجاوز كابتشا أو جدار دفع أو اشتراك أو تسجيل دخول.
- لا تحمّل/تخزّن النصوص الكاملة للوثائق القانونية.
- لا تستخرج قواعد بيانات أو تجري زحفًا واسعًا (crawl) للموقع.
- لا تتفاعل مع المساعد الذكي بما يستهلك اشتراكًا — تكتفي برصد وجوده.
- لا تُدخِل بيانات دفع حقيقية ولا تحفظ بيانات حساسة.
- مقاييس مثل TTI/TBT تتطلب Lighthouse وتُترك `null` عمدًا (نستخدم Performance APIs
  المدمجة لضمان التشغيل في أي بيئة).

> التقييمات الآلية مؤشرات للمراجعة البشرية، وليست حُكمًا نهائيًا؛ تُستكمل بفحص
> اللقطات وملفات JSON.
